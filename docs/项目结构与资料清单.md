# 第一部分 · 项目结构

## 1.1 顶层：一张图看懂

```
bazipaipan/
├── src/        ← 全部源代码（前端页面 + 后端服务 + 核心引擎）
├── admin/      ← 管理后台前端（独立的第二个网页）
├── docs/       ← 全部文档（规则 / 架构 / 决策 / 计划 / 进度）
├── seeds/      ← 知识数据种子文件（星座、古籍…，可导入数据库）
├── scripts/    ← 运维脚本（备份 / 冒烟 / 导入 / 部署）
├── tools/      ← 开发辅助脚本（生成报告 / 集成测试）
├── tests/      ← 端到端测试
├── public/     ← 网站图标等静态资源
├── deploy/     ← 部署脚本
├── data/       ← 数据库文件 + 临时数据（不提交 git）
├── logs/       ← 运行日志（不提交 git）
├── reports/    ← 生成的报告产物（不提交 git）
├── dist/       ← 编译产物（自动生成，不提交 git）
└── node_modules/ ← 依赖包（自动生成）
```

> **一句话**：`src` 是主体，`admin` 是后台，`docs` 是说明书，`seeds` 是数据，`scripts` 是工具。

## 2.0 先说结论（关于命名）

1. **每条资料有两个名字**：
   - **key（存储编号）** = 内部用的名字，存在数据库里，代码靠它找资料。就是这个有英/拼音之分。
   - **中文名** = 你在后台看到的那个大字（比如「白羊座」）。
2. **你在后台实际看到的**：**大字是中文名**，下面跟一行小号灰色代码才是 key。所以**不影响你看懂**，但小灰字确实可能是英文。
3. **命名语言分布**：老资料基本是**拼音**（你能读）；**新加的**（星座、MBTI/格局）多了**英文**。

# 第三部分 · 维护说明（重要）

**以后新增资料落库（比如以后加更多星座/古籍/断语），本文件的第二部分要跟着更新。**

三种更新方式，任选：

1. **一键列出当前库里的全部资料**：
   ```bash
   npm run kb:list
   ```
   读 `data/mingli.db` 的 `knowledge_assets` 表，按分类列出所有条目的 key + 说明 + 状态。
   （换库：`node scripts/kb-inventory.mjs --db 路径`）

2. **直接让 AI 更新**：对球球说一句「把《项目结构与资料清单》里的资料清单更新一下」，
   AI 会读库、对比、补齐新增条目。

3. **手动加**：新增条目在对应分类表里补一行（`key | 中文名 | 作用 | 命名语言`）。

> 判断「有没有新数据」的简单办法：跑 `npm run kb:list`，对照第二部分分类的条数是否变化。

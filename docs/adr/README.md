# 🏛️ 架构决策记录（Architecture Decision Records, ADR）

> **用途**：把"为什么这么设计"固化下来。每条 ADR 记录一个**不可轻易逆转**的架构决策的
> **背景 / 备选 / 结论 / 代价**，让半年后的人（包括我们自己）不用重新踩一遍坑。
>
> **来源**：2026-09-28 架构评审（`../arch/ARCHITECTURE-REVIEW.md`）+ 同日「架构决策评审会」。
>
> **纪律**：一条决策一个文件；**只增不改** —— 决策变更时新写一条，并把旧的标为
> `Superseded by ADR-XXX`，保留历史。改代码前先看对应 ADR。

---

## 状态说明

| 状态 | 含义 |
|---|---|
| `Proposed` | 已提出，待评审会 / 负责人批准 |
| `Accepted` | 已采纳，作为当前约束执行 |
| `Deprecated` | 不再适用（但保留记录） |
| `Superseded by ADR-XXX` | 被新决策取代 |

## 评审节奏（**先骨架、后完善**）

> 原则：先把**决定系统形态**的承重柱立住（骨架），再逐步打磨运营/治理细节（完善）。
> 骨架项变动代价最大、影响面最广，必须先定；完善项可以在迭代中陆续收敛。

### 第一批 · 骨架级（建议本次评审会逐条过）

**决定系统"长什么样 / 怎么算 / 怎么收钱 / 怎么不丢数据"** —— 六根承重柱：

| ADR | 一句话 |
|---|---|
| 001 | 不拆微服务，加固单体 + 预留三条拆分缝 |
| 002 | 留用 SQLite，但定义 5 条换 PG 的**触发条件** |
| 004 | 额度**幂等消费 + 追加式台账**，门禁转正 |
| 005 | **计算权威收敛到服务端**（堵住客户端伪造 chart） |
| 008 | 备份脚本 + 恢复演练 + 版本化迁移链 |
| 009 | 真实支付 + **回调幂等**（不重复发货） |

### 第二批 · 完善级（Phase 5~6 迭代中收敛）

**决定"怎么运营 / 怎么治理 / 怎么演进"**：

| ADR | 一句话 |
|---|---|
| 003 | LLM 网关：缓存 / 路由 / 核算 / 降级 / 限流 |
| 006 | 生辰 PII 的告知同意 + 导出删除 |
| 007 | 健康检查分级 + 分维度指标 + traceId + SLO |
| 010 | 版本策略 + `/api/admin` 兼容层到点即删 |

## 骨架实施顺序（建议）

> 原则：**先补"不会让服务中断"的承重柱，再动请求路径**。每片独立可交付、可回滚，
> 且都以"不影响线上服务"为前提（对齐"服务跑起来"的要求）。

| 序 | 项目 | 对应 ADR | 风险 | 是否需前端改造 | 说明 |
|:--:|---|:--:|:--:|:--:|---|
| 1 | **备份脚本 + 恢复演练** | 008 | 🟢 极低 | 否 | 纯运维、纯新增，不碰请求路径；先止住"数据全丢"的沉默风险 **✅ 已完成** |
| 2 | **健康检查分级 + traceId** | 007 | 🟢 低 | 否 | `/api/health/deep` + `/api/metrics` + `X-Trace-Id`；admin/app 分维度指标 **✅ 已完成** |
| 3 | **计算权威收敛（重算校验闸门 + 权威端点）** | 005 | 🟡 中 | 否（兼容旧流） | `chartHash` + `POST /api/v1/app/chart` + `chart_verify_mode` 闸门 **✅ 已完成** |
| 4 | **额度门禁转正 + 幂等台账** | 004 | 🟡 中 | 否 | `quota_ledger` + 事务化扣减 + 两阶段退款 **✅ 已完成** |
| 5 | **真实支付接入 + 回调幂等** | 009 | 🔴 高（外依赖） | 否 | 幂等结算单一入口 + 回调验签端点 **🔶 框架已就绪**；真实渠道依赖**备案域名 + HTTPS + 商户资质** |
| 6 | **PII 合规底座** | 006 | 🟡 中 | 是（注册/排盘入口） | 后端：同意留痕 + 导出 + 删除**🔶 已就绪**；隐私政策/协议文案与前端入口待补 |

> 1~4 属于"可立即开工、不依赖外部资质"的骨架；5~6 依赖域名/资质/文案，需与产品侧协同。

## 新 ADR 模板

```markdown
# ADR-XXX: [决策标题]

- **状态**: Proposed | Accepted | Deprecated | Superseded by ADR-XXX
- **日期**: YYYY-MM-DD
- **决策者**: [负责人]
- **类别**: 🧱 骨架 | 🔧 完善
- **关联**: [相关文档 / ADR / 代码路径]

## 背景（Context）
是什么问题促使我们做这个决策？

## 驱动因素（Decision Drivers）
影响决策的关键约束与力量。

## 备选方案（Options）
至少两个，各自写清**代价**。

## 决策（Decision）
我们选择什么？为什么？

## 后果（Consequences）
正向 (+) / 负向 (−) / 中性或风险。

## 复审触发条件
什么情况下需要重评此决策？

## 关联
```

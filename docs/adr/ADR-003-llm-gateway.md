# ADR-003: 引入 LLM 网关（缓存 / 路由 / 核算 / 降级 / 限流）

- **状态**: `Proposed`
- **日期**: 2026-09-28
- **决策者**: 田哥
- **类别**: 🔧 完善（AI 成本与弹性）
- **关联**: `../arch/ARCHITECTURE-REVIEW.md` §4.3、`src/server/lib/llm.ts`、`src/server/config/index.ts`

---

## 背景（Context）

AI 是目前**最大的成本与弹性敞口**：

- ❌ 无响应缓存 → 常见问题重复付费；
- ❌ AI 接口**无限流** → 单用户可无限刷 LLM，成本失控；
- ❌ 无 token 成本核算 → 无法回答"这个用户花了多少钱"；
- ❌ 供应商只有**全局唯一** `isDefault=1` → 无故障转移，一次超时即用户可见失败；
- ❌ 无分级模型 → 文档设想"常见走便宜模型、深度走强模型"未落地。

这些能力当前散落在 `lib/llm.ts` / `config/index.ts` / `api/chat.ts`，缺乏统一收敛点。

## 驱动因素（Decision Drivers）

- 成本必须**可预测、可核算**，否则商业化无以为继。
- 单一供应商 = 单点故障，直接影响可用性。
- 分级模型是 Freemium 差异化的技术前提。
- 收敛点必须**薄**（只做横切关注点），否则变成新的复杂度中心。

## 决策（Decision）

把散落的 LLM 调用**收敛为一个"LLM 网关"内部模块**，统一提供：

1. **响应缓存**：按 `(promptHash, model, params)` 缓存，命中零成本；
2. **成本核算**：记录每次调用的 token 用量与折算费用，落账单表（支撑"这个用户花了多少钱"）；
3. **限流 + 配额门禁**：接 ADR-004 的**幂等额度**；
4. **分级路由**：免费用户 → 便宜模型，付费 → 强模型；
5. **故障转移 + 熔断**：主供应商失败自动切备用；连续失败熔断 + 半开重试。

> 网关保持**薄**：只做缓存 / 计量 / 路由 / 保护，**不含业务逻辑**，业务留在 `agents/` / `workflows/`。

## 后果（Consequences）

**正向 (+)**
- 成本可预测、可核算；单点故障不再直接暴露给用户；为"分级模型"商业化铺路。

**负向 (−)**
- 网关本身是新的复杂度中心 → 必须严守"薄"的边界。

**中性 / 风险**
- 缓存一致性：同一问题在不同上下文下答案不同 → **缓存键必须包含所有影响输出的要素**
  （系统提示、知识版本、模型、参数）。

## 复审触发条件

- 供应商数量 / 路由策略变化；
- 缓存命中率长期过低（说明缓存键设计有问题）；
- 引入 RAG 后上下文变化 → 缓存需纳入检索结果指纹。

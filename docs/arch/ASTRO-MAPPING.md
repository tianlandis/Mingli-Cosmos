# 星座 ↔ 八字 精确映射算法（太阳星座）

> 状态：已实现 ｜ 代码：`src/server/lib/astro-mapping.ts` ｜ 测试：`src/server/lib/__tests__/astro-mapping.test.ts`（12 项）
> 最后更新：2026-09-29

## 一、原理：为什么这个映射是"精确"的

太阳星座与八字月支**共享同一个天文自变量——太阳黄经**，两者都是它的确定性阶梯函数：

| 体系 | 分界 | 黄经 | 例 |
|---|---|---|---|
| 太阳星座 | 「中气」时刻 | 30° 的整数倍 | 春分 0° 起白羊、谷雨 30° 起金牛 |
| 八字月支 | 「节」时刻 | 15°+30k | 惊蛰 345° 起卯、清明 15° 起辰 |

24 节气 = 12 节 + 12 中气，**同一张节气表同时给出两类分界的精确时刻**（lunar-typescript，精确到秒）。因此：

1. **星座判定 = 查表中气**：出生时刻之前最近的一个中气即星座起点。不使用"3 月 21 日"这类近似日期表（每年浮动 1~2 天，且未计出生时刻）。
2. **与排盘引擎同源零歧义**：引擎月柱本就用同一张节气表定月支，映射与排盘天然一致，可做一致性校验。
3. 分界错开 15°（半个月）→ **每个星座恰好横跨两个月支各一半**；中气即月支的月中点（"中气"得名本义）。

## 二、映射公式

记支序 `M = ['辰','巳','午','未','申','酉','戌','亥','子','丑','寅','卯']`（M[m] 的节在黄经 15°+30m），星座 `s`（0=白羊 … 11=双鱼）：

```
星座 s 横跨：前半段 ∈ M[(s-1) mod 12] 月，后半段 ∈ M[s mod 12] 月
```

| 星座 | 元素 | 横跨月支（前半 / 后半） | 星座 | 元素 | 横跨月支 |
|---|---|---|---|---|---|
| 白羊 | 火 | 卯 / 辰 | 天秤 | 风 | 酉 / 戌 |
| 金牛 | 土 | 辰 / 巳 | 天蝎 | 水 | 戌 / 亥 |
| 双子 | 风 | 巳 / 午 | 射手 | 火 | 亥 / 子 |
| 巨蟹 | 水 | 午 / 未 | 摩羯 | 土 | 子 / 丑 |
| 狮子 | 火 | 未 / 申 | 水瓶 | 风 | 丑 / 寅 |
| 处女 | 土 | 申 / 酉 | 双鱼 | 水 | 寅 / 卯 |

相邻星座共享月支形成闭环（支序链），可用于自检。

## 三、API（`src/server/lib/astro-mapping.ts`）

```ts
getSolarSign(birth: Date): SolarSignInfo
// { index, name, en, element, since(起点中气时刻), until(下一分界时刻) }

getSignBranchPair(signIndex): [前半支, 后半支]

mapSunSignToBazi(birth: Date, monthBranch: string): AstroBaziMapping
// monthBranch 传 engine BaZiResult.monthPillar.branch
// { sign, branchPair, consistent, phase: '前半'|'后半', relation: 人读文案 }
// 月支不在区间内直接 throw（映射与排盘不一致 = 引擎或映射有 bug，熔断）
```

调用示例（C 端排盘后）：

```ts
const bazi = await calculateBazi(input)
const m = mapSunSignToBazi(new Date(y, mo-1, d, h, mi), bazi.monthPillar.branch)
// m.relation → "双鱼座（水象）：横跨寅月后半与卯月前半；本人月支为卯 → 生于双鱼座后半段（卯月节后）"
```

## 五、边界与后续

- 本映射**仅覆盖太阳星座**；月亮/上升星座需出生时间+地点的星历计算（候选：`astronomy-engine` 纯 JS / Swiss Ephemeris），另立方案。
- **禁止**将映射写入 `src/engine/`（封版）；后续若做星座完整体系，按 ADR-011 实现 `SystemEngine` + registry 注册。
- 星座×八字×MBTI 融合解读属**内容层**：落 `knowledge_assets`（标注来源与置信度），LLM 只做表达；元素（火土风水）字段已在本模块预留。

## 六、语料相容性（2026-09-29 矛盾检测）

**问题**：星座由出生月份决定、MBTI 由四柱决定，两者统计独立——12 星座 × 32 MBTI 档案（16 型 × A/T）的任意组合都会真实出现在同一用户身上。星座语料若写方向性人格断言，必然与一部分 MBTI 命书语料（`mbti-expression-corpus.ts`，A↔身强 / T↔身弱）矛盾。

**量化结果**（`src/server/lib/corpus-consistency.ts` + 同目录测试，11 项）：

| 语料 | conflict | tension | 结论 |
|---|---|---|---|
| 网络典型星座话术 × 32 档案 | **576 / 384 组合** | 192 | 12 星座全部中招，照搬必炸 |
| 官方 zodiac.sample.json 的 traits | 32（仅 2 星座） | — | 连样例的「热情/务实」都带断言 |
| 能量风格措辞改写 × 32 档案 | **0** | **0** | 写作规范可行 |

**写作规范（星座语料准入标准）**：
1. 禁止对 MBTI 五组维度做方向性断言：E/I（外向内向）、S/N（实感直觉）、T/F（思考情感）、J/P（计划随性）、A/T（自信动荡）；
2. 只写「能量风格/节奏/需求倾向」（如"开局的冲劲""持久的耐力"），不写"天生领袖""敏感多疑"这类行为人格断言；
3. 每条星座 traits 导入前过 `detectConflicts`（CI 守卫，批次 C 检索式注入的前置闸门）；词表外词一律中性不误报，词表可随语料迭代扩充。
